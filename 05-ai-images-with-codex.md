# 05: On-brand images with the Codex CLI

Every image on the site (hero, six product scenes, backgrounds, a character) was generated by the OpenAI **Codex CLI**, which lets a GPT model call its built-in image tool. The trick that keeps them on-brand is attaching the brand's own images as references on every request. Working tool: `reference/tools/codex-image.mjs`. Prompts: `reference/art/`.

## The method

1. **Two references, always attached:** the logo (identity authority) and one hero image of the product in its world (style authority).
2. **A "style lock" prefix** (`reference/art/style-lock.md`) prepended to every prompt. It says what reference 1 and 2 are, the art style in concrete terms (materials, light, colour, fog, reflections), what the product must look like, a **text rule** ("no other text anywhere") and a **composition rule** (everything inside the frame, leave negative space for headlines).
3. **A per-image prompt** in `shots.json`: the setting, the signature ingredients, the composition (where the subject sits), and the accent colour.
4. **Chain images**: the wide scene for a product is generated *from that product's portrait image* as a third reference, so the jar and label match.
5. **Batch in parallel** (6 to 8 at once); each takes 1 to 2 minutes.
6. **Review every image by eye.** Label spelling, cut-off objects, stray text, mood.

## How it is called (the non-obvious parts)

- Use `codex exec --skip-git-repo-check -m <model> "<prompt>" -i ref1 -i ref2`.
- The prompt must come **before** the `-i` flags (`-i` swallows everything after it).
- On Windows run `node .../@openai/codex/bin/codex.js` directly; the `.cmd` shim drops file paths that contain spaces.
- Close stdin, or Codex waits for input.
- Each call is a new session that prints `session id: <uuid>`; the images land in `~/.codex/generated_images/<uuid>/`. Copy only from your own session's folder so parallel runs never mix up.
- The agent sometimes saves an extra copy into its working directory. Run it from a throwaway temp folder so your project isn't littered.
- Use `--force` semantics deliberately: the tool never overwrites an existing file unless asked.

## Prompt patterns that worked

- **Name the label text exactly** ("label reading exactly BLOOD MOON GARLIC") and add the rule "spell the flavour name letter for letter". It got every label right.
- **One dominant setting per product** plus 3 to 4 signature props (lava and chillies; blood-red moon and garlic; amethyst cave; glacier and mint). Distinct worlds, same jar.
- **Say where the subject stands and how big** ("dead centre, about 45 percent of the frame height"; "centre at 68 percent of the width").
- **Ask for calm dark space where text will go.**
- **Faceless character:** "no face is visible at all" gives a safe, mysterious human presence.
- **Alpha is not available** from this tool. Design so black backgrounds blend (dark site, vignettes) rather than needing cut-outs.

## After generation

- Convert with a script (WebP at several widths, tiny blur placeholders, a dominant colour) and record sizes in a manifest the templates read.
- Bake extra assets from the art: a **depth map** for parallax (`reference/tools/depth.py`, Depth Anything V2 small ONNX, runs on CPU) and **transparent logo pieces** (split the logo by connected components so no stray rays end up in the wordmark).
- Make one social card (1200x630) per product from its scene.

## Limits to be honest about

- It is a stand-in for real photography. Real photos of the real product always win; the pipeline accepts them (`photo-<name>-card.jpg`).
- The hero was generated at 1672 px wide; on very large screens it is slightly soft. An upscaler (Real-ESRGAN) or a photograph fixes that.
- It uses your ChatGPT plan; tell the site owner before running big batches.
